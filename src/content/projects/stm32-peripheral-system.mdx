## Overview
An STM32F103 system connects an MPU6500 inertial sensor, W25Q64 SPI flash, and a Python desktop controller. The same UART interface supports an interactive ASCII shell and a variable-length binary protocol.

## System architecture
<div className="architecture"><span>MPU6500 sensor</span><b>→ I²C →</b><span>STM32 / FreeRTOS</span><b>→ UART →</b><span>Python host</span></div>

Sensor, logger, and shell tasks separate acquisition, storage, and commands. A mutex protects shared sensor data; a receive queue transfers serial input to the parser. The logger writes to external flash over SPI.

## Implementation
The byte-by-byte parser waits for a `0xAA` start byte, reads a command and payload length, then validates an XOR checksum. The source rejects payload lengths above 16 bytes. The host application uses Tkinter and pyserial for commands and telemetry.

## Technical challenges
Flash page boundaries and shared-memory access are the main design constraints. The firmware uses a packed 16-byte log record to divide a 256-byte page evenly. A mutex coordinates sensor updates and logger snapshots.

## Results and current limits
The public repository includes firmware, a host GUI, protocol test tooling, and demonstrations. Logging is currently limited to a single erased sector. Multi-sector logging, DMA transfers, wear leveling, and CRC-16 are future work, not implemented portfolio claims. Hardware performance has not been independently benchmarked for this portfolio.
